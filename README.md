# dsh-recall

DSH 的「撤回」插件：只撤**最后一条用户消息**，把对话与工作区文件一起回退到这一轮开始前，并生成一个新的干净分支会话。

## 功能

- 聊天界面里，每条**最后一条用户消息**右上角会出现一个回旋箭头「撤回」按钮。
- 点击后：
  1. 弹窗确认（`window.confirm`）。
  2. 生成一个**不含这条消息及其之后内容**的新分支会话，消息原文回到新会话的输入框，可改动后重发。
  3. **文字与附件一起回填**：这条消息里带的图片、普通文件都会重新放回新会话的输入框（图片带预览、文件显示成附件卡），可删可换再发。
  4. 工作区里这一轮被 AI 改动过的文件**还原**、这一轮新增的文件**删除**（基于每轮开始前的快照）。
  5. **原会话保留**在会话列表中可回看，不会被删除。
- 撤回按钮只挂在「最后一条用户消息」上；更早的消息请用框架自带的「分支」功能另开会话。

## 安装（一行命令，即装即用）

前提：已装好 DSH，且使用 `web` profile。

```bash
dsh plugin --profile web add https://github.com/Zok66/dsh-recall
```

**就这一条命令。** 从 GitHub 直装，不需要手动下载、不需要把仓库放到某个目录、不需要改任何配置。

装完后**手动重启 `dsh web`**（或刷新前端页面），撤回按钮即生效。

### 装完怎么确认成功

```bash
# 看插件是否在清单里
dsh plugin --profile web list

# 看启动日志是否打了补丁
grep -i recall ~/.dsh/dsh-web.log | tail
```

正常会看到：

```
[recall] 前端撤回按钮已注入
[recall] 已启用：撤回按钮（仅最后一条消息）+ 附件回填 + 文件快照与还原
[recall] 附件读取路由已注册: /api/recall.attachment
[recall] 撤回还原路由已注册: /api/recall.restore
```

### 卸载

```bash
dsh plugin --profile web remove dsh-recall
```

### 本地开发 / 改代码时

如果你自己改了源码想立刻生效，用 `link:` 指向本地目录：

```bash
dsh plugin --profile web add link:/绝对路径/dsh-recall
```

> 注意：`link:` 指向的目录**不要放在你的会话工作区里**，否则撤回时的文件回退可能波及它（插件已内置自我目录保护，但挪出去更干净）。

## 撤回语义（请注意，跟普通聊天撤回不同）

本插件的「撤回」不是只删一条气泡，而是一次**分支 + 文件回退**：

- **对话**：fork 出一个新会话，新会话从「被撤消息之前」开始，之前的对话全部保留，被撤消息及其之后的内容都不在新会话里。原会话完整保留在列表。
- **文件**：插件在每一轮开始前对当前工作区（会话 `cwd`）做快照。撤回时按快照把被改的文件还原、把新增的文件删除。

适用场景：发了一条消息、AI 改了一堆文件，你后悔了，想「连话带文件一起回到这一轮之前」再重来。

## 注意事项

1. **首次启动会改写 DSH 安装目录里的 chat 前端文件**（`@deepseek-ai/dsh-client-ui-chat/lib/client.js`），注入撤回按钮。
   这是设计内的「自愈补丁」——DSH 升级或重装把改动覆盖掉后，插件下次启动会**自动重新打上**，不影响正常对话。被改写文件会自动备份为 `client.js.orig-recall`。
2. **撤回会动工作区文件**，请在意的目录上谨慎使用（例如不要把重要未提交改动留在一轮里才去撤）。
3. 若撤回的是会话里**唯一一条**用户消息，无法在保留会话内容的同时把它移除（新分支会变成空白会话导致界面错乱），此时插件**只把原文与附件放回当前会话输入框**，不创建分支，并提示你「如需完全重来，请新建会话」。
4. 文件快照默认存放在 `$DSH_HOME/.recall-snapshots/`（DSH 运行时已注入 `DSH_HOME`），单文件上限 8MB、单会话快照上限 512MB，超出从最旧的轮次开始自动清理。
5. **插件自身目录受保护**：如果你把插件源码装在工作区里（常见做法，例如本插件就在 `/sdcard/Zorrose-DSHA/日常/dsh-recall`），撤回时插件会**主动跳过自己的安装目录**，不会把「本轮新增的插件文件」当成 AI 产物删掉。
   这条保护是实测踩坑后加的：早期版本确实会在撤回时删掉自己，导致 dsh 下次启动报 `ERR_MODULE_NOT_FOUND`。
6. **附件回填的真实性说明**：图片优先用会话自带的附件读取（带引用校验）取回；普通文件由插件在主机侧注册的只读路由 `/api/recall.attachment` 取回原始字节，再重新组装成 `File` 放回输入框。
   - 该路由挂在 connection 的认证栅栏后，只接受「本会话日志里真实引用过」的 `attachmentId`，不接受任意路径或任意 id。
   - 附件体积过大时会按平台自身的附件上限走，超限的附件会跳过回填（文字仍照常回填）。
   - 原附件对象本身不可变，回填是重新读取同一份字节，内容与当初发送的完全一致。

## 只对「撤回」生效，不影响框架自带「分支」

文件还原由前端撤回时**显式请求** `POST /api/recall.restore` 触发，主机侧不再监听 `session/created`。

原因：框架自带的「分支」和本插件的「撤回」都走 `sessions.fork`，子会话都带 `header.parentSession`，主机侧从事件本身无法区分两者。早期版本靠 `parentSession` 猜测，导致**点普通分支也会把工作区文件回退/删除**。现已彻底改为显式请求。

## 已知限制（重要）

1. **超过 8MB 的文件不会被备份**，因此撤回时无法恢复它的改动。
   但插件会把这些文件的路径登记进快照，**保证它们不会被误删**（不会当成「本轮新增」清掉）。
   若某个超大文件在本轮被 AI 改坏，撤回后需要主人手动取回。
2. 撤回是**一次性**的：还原完成后不会再保留「撤回的撤回」。

## 附件回填是怎么实现的（给维护者）

撤回时前端只能从会话快照拿到附件**引用**（`attachmentId`、`name`、`mediaType`…），拿不到字节：

- **图片**：`session.readAttachment(id)` 就能读回（会校验该图片确实被本会话引用）。
- **普通文件**：前端没有任何 API 能读 `file` 块的字节，所以由插件在主机侧注册 `/api/recall.attachment`，从 `ctx.attachments.readFileStream(ref)` 读出来交给浏览器。

拿回字节后，插件用与「拖拽/选择文件」完全相同的通道放进草稿：

```js
const drafts = conversation.createDrafts(sessionId, files)   // 建草稿附件（图片有预览，普通文件自动后台上传）
shell.addFiles([], drafts.map((d) => d.id))                  // 挂到输入框的附件栏
```

这样附件会像手动添加的一样出现在输入框上方，可以单独删除、可以随文字一起重发。

## 目录结构

```
dsh-recall/
├── package.json           # 声明 dsh.bundle，让 DSH 自动加载
├── cordis.patch.yml       # bundle 挂载声明
├── README.md
└── lib/
    ├── index.js           # 插件入口：启用补丁 + 每轮快照 + 撤回时还原文件
    ├── client-patch.js    # 给聊天前端注入「撤回」按钮与附件回填（自愈补丁，自动定位目标文件）
    ├── attachment-route.js # 主机侧只读附件路由（普通文件字节回读）
    └── snapshot-store.js  # 工作区文件快照 / 还原核心
```

## 卸载

```bash
dsh plugin --profile web remove dsh-recall
```

卸载后插件不再加载，但已注入到 chat 前端文件里的撤回按钮代码仍残留（自愈标记不会自动清除）。如需彻底还原前端，可从 `client.js.orig-recall` 备份恢复，或重装 DSH 覆盖该文件。
